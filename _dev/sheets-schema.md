# sheets-schema.md — スプレッドシート構造・列マッピング

アプリが読み書きする各シートの構造を記録する。列番号は 0-indexed（コード上の配列インデックス）で記載。

---

## スタッフ情報シート

行 0: ヘッダー行（読み飛ばし）
行 1〜: データ行

| 列名（アルファベット） | index (0始まり) | 内容 | 備考 |
|---|---|---|---|
| B | 1 | 拠点 | |
| E | 4 | 生年月日 | Excelシリアル値またはYYYY/MM/DD形式 |
| H | 7 | 出身都道府県 | 末尾に「都道府県」が付く場合あり |
| I | 8 | 血液型 | 「A型」または「A」など |
| J | 9 | 入社日 | Excelシリアル値またはYYYY/MM/DD形式 |
| K | 10 | 動物占い | |
| N | 13 | 動物占い（別列）| profile APIではrow[10]使用、me APIではrow[13]使用 ※要確認 |
| R | 17 | 星座 | |
| T | 19 | 名前（フルネーム） | アプリ内の主キー的な存在 |
| U | 20 | ユーザーID | me API・認証で使用 |
| W | 22 | ロール | 「アルバイト」「社員」「管理者」「業務委託」 |
| X | 23 | 有効フラグ | 「TRUE」で有効（大文字小文字どちらもあり） |
| Z | 25 | 連絡先（電話番号等） | |
| AB | 27 | 性別 | 「男」「女」 |
| AC | 28 | 役職 | 「ディレクター」「準ディレクター」等 |
| AD | 29 | ログイン情報 | admin/login-info APIで使用 |

**注意：**
- 行 0 はヘッダーなので `rows.slice(1)` でデータ取得
- 「有効」がTRUEのスタッフのみ表示対象（admin機能を除く）
- 名前（T列）はシート上の行順 = 入社歴順（BottomNav・Sidebarの並び順の基準）

## 知識シート

行 0: ヘッダー行（product名など）
行 1: サブヘッダー行
行 2〜: データ行（`knRows[2]`から読む）

| index | 内容 | 備考 |
|---|---|---|
| 0 | アルバイト名 | 短縮形（例：「木付」）。スタッフ情報T列のフルネームとは一致しない |
| 1 | 担当社員の姓 | 「なし」「未定」の場合は担当なし |
| 2〜 | 各商品のスキル習熟度 | C列以降。行 0 または行 1 が商品名 |

**名前照合の注意：**
- 知識シートA列は短縮名（「木付」）、スタッフ情報T列はフルネーム（「木付翔太」）
- 結合時は `startsWith` を使う（社員連絡先API・担当APIで採用済み）

## 合算データシート

各月の日報・営業実績を GAS が集計して書き込む。`/api/data` および `/api/yearly` で読み込む。

| 列 | 内容 | 備考 |
|---|---|---|
| A | タイムスタンプ | フォーム送信日時 |
| B | 勤務日 | `yyyy/MM/dd` 形式（GASで`setNumberFormat`を適用） |
| 他 | 各種実績列 | aggregator.ts で集計 |

**運用上の注意：**
- GAS の `mergeSheets_Complete` が全削除→上書きで管理
- FormSheetA でグループ化（折りたたみ）中に実行するとデータが消える（経理スタッフとの運用ルール要確認）

## 勤怠報告受信録

Talknoteの「★関東社員★勤怠報告★」ノートへの投稿を、GAS（`talknote.gs`）がGmail通知経由で記録する。
他の受信録シート（実績受信録・終了報告受信録）と同じ3列構成。`/api/kintai` で読む。

| 列 | index | 内容 |
|---|---|---|
| A | 0 | 受信日時（`yyyy/MM/dd HH:mm:ss`） |
| B | 1 | 送信者＝**報告した社員**（欠勤した本人ではない） |
| C | 2 | メッセージ内容（投稿本文そのまま） |

**本文のフォーマット：**

```
日付：8月27日(木)
勤怠：当欠
理由：体調不良

勤務地：アリオ北砂
スタッフ：救仁郷リアム
勤務時間：
休憩：無
```

**注意：**
- 投稿の日付に年がないため、受信日時の年から補完する（`/api/kintai` の `resolveDate`）
- 集計対象は「スタッフ：」欄の名前。B列の送信者ではない
- 全角・半角どちらのコロンも来るため、パーサは両方を許容している
- **「勤怠：」の行がない投稿は取り込まない**（雑談や、別スタッフの補足だけの投稿を除外するため）
- **1投稿＝1人**として扱う。1つの投稿に「※〇〇くん」と別スタッフの補足が続く書き方があるが、そのブロックには勤怠区分がないため独立した記録にはならない
