## 2026-06-03: 自動遡りのコールバック方式でSheetsクォータ超過
- 症状: 「データがありません」→自動で月を遡る処理を実装後、Google Sheetsの「Read requests per minute per user」クォータエラーが頻発した
- 原因: AttendanceTableからpage.tsxへのコールバック方式だと「データなし検知 → setSelectedMonth → 再fetch → データなし → setSelectedMonth → ...」が高速で繰り返され、12回のSheets読み取りが数秒以内に走った。各月は異なるURLなのでVercelキャッシュが効かず毎回Sheetsを読む
- 解決: コールバック方式を廃止し、`fetchData`内のforループで最大12ヶ月を順次チェックする方式に変更。ループが1関数内に収まるため制御しやすい
- 再発防止: 「月を変えながらAPIを複数回叩く」処理はコールバック連鎖ではなく、必ず1つの非同期関数内のループで実装する

## 2026-06-05: 担当タブがPCサイドバーに表示されない
- 症状: スマホのBottomNavには担当タブが出るがPCのSidebarには出ない
- 原因: Sidebar.tsxのsecretModeフィルターが `item.id === 'growth' || item.id === 'tardiness'` とハードコードされており、新しいタブ追加時に更新し忘れた
- 解決: フィルター条件に `|| item.id === 'tantou'` を追加
- 再発防止: secretMenuに新タブを追加するときはSidebar.tsxのsecretModeフィルター（62〜64行付近）とBottomNav.tsxのSECRET_NAV_ITEMSの両方を必ず確認する

## 2026-06-05: clasp push で別プロジェクトのファイルを誤pushした
- 症状: sync-nippo GASに `sync-shift.gs`・`send-staff-id.gs` が混入した
- 原因: `gas/` フォルダにファイルが混在した状態で clasp clone → push したため、全ファイルが sync-nippo プロジェクトにpushされた
- 解決: `.claspignore` で対象外ファイルを除外して再push → GASから削除された。フォルダを `sync-nippo/` と `sync-shift/` に分離
- 再発防止: clasp push 前に必ず `gas/` のフォルダ構成を確認。各プロジェクトは専用サブフォルダで管理する

## 2026-06-09: 実績報告が「その他」に入り現場に紐づかない
- 症状: 6/7の実績報告が6/9に受信され、6/7を開くと「その他」グループに表示された
- 原因①: GASのメール処理が翌日以降になるケースがある。受信日付（6/9）で絞り込むとシフト日付（6/7）と一致せず現場が特定できない
- 原因②: 実績報告メッセージ本文には「6月7日(日)」という営業日が書かれている
- 解決: 受信日付でのフィルタリングを廃止し、メッセージ本文の「M月D日」を正規表現で抽出して営業日で照合する方式に変更
- 再発防止: 受信録系のデータは「メールを受信した日 ≠ 営業日」になり得る。日付フィルタはメッセージ本文を優先する

## 2026-06-09: 実績報告タブのMNP/新規バッジが過大カウント
- 症状: 実績報告タブで「MNP 9台・新規 10台」と表示された（正しくはMNP 2台）
- 原因: `countMnpNew` がTalknoteの短文メッセージ向けに作られており、実績報告の構造化テキスト内の「au MNP：」「UQ MNP：」「新規HS：2」などを全部拾ってしまった
- 解決: 実績報告タブのバッジ計算は実績報告テキストを解析せず、Talknoteタブと同じ `data.siteMap` を流用する（`badgeSiteMap` プロップで渡す）
- 再発防止: 構造化された長文テキストに対して `countMnpNew` を使うと誤カウントする。異なるフォーマットには別の計算ロジックが必要

## 2026-06-05: 担当タブで担当社員名が全員空になる
- 症状: 担当タブにアルバイト名と役職は表示されるが「担当：〇〇」の社員名が全員空

- 再発防止: スプレッドシート間で名前を結合するときは必ずフォーマットを確認する。知識シートは短縮名、スタッフ情報T列はフルネームという違いがある

## 2026-06-30: GAS syncAllが6分でタイムアウトする
- 症状: syncAll実行時に「シフト同期開始: 2026-06」のログ1件だけで6分後にExceeded maximum execution timeエラー
- 原因: GAS ConfigにSYNC_URL（旧: sales-studio-iota）とSYNC_URL_NEW（新: dawin-sales-studio）の2つのURLがあり直列実行。旧URLは正常だが新URLのVercel Functionがタイムアウト。原因はVercel FunctionのリージョンがNorth America(iad1)なのにNeon DBがSingaporeにあり、DB書き込みクエリが10秒制限を超えていた
- 解決: Vercel ダッシュボード Settings → Functions → Function Region を Asia Pacific (sin1 = Singapore) に変更してリデプロイ
- 再発防止: Vercel FunctionのリージョンはNeon DBのリージョンに合わせること。dawin-sales-studioのNeonはAWS Asia Pacific 1 (Singapore)

## 2026-07-10: 獲得pt合計が四捨五入されて表示される
- 症状: 合計5.75ptが5.8ptと表示された
- 原因: AttendanceTable.tsx の `Math.round(staff.total * 10) / 10` が小数第1位に丸めていた
- 解決: `staff.total` をそのまま使用（aggregator.tsのsafeAddが小数第2位で管理しているため精度は保証済み）
- 再発防止: 表示層で丸めを加えない。safeAdd（* 100 / 100）が唯一の丸め箇所

## 2026-07-10: 自己クロ合計が4.6999...と表示される浮動小数点バグ
- 症状: 1.8 + 2.3 + 0.6 = 4.6999999999999999 と表示された
- 原因: 獲得pt修正時に totalSelfClose の `Math.round(* 10 / 10)` も除去したため、JS の浮動小数点誤差が露出した
- 解決: `reduce` 内で各加算後に `Math.round((sum + val) * 100) / 100` を適用（safeAddと同方式）
- 再発防止: 小数を含む累積加算は必ずsafeAdd方式（* 100 / 100）を使う。丸めを「全部取る」か「全部残す」かで中途半端にしない

## 2026-07-10: Talknoteカードに関東社員の投稿が混入する
- 症状: ☆関東社員☆ノートの投稿がTalknoteカード（稼働ビュー）に表示された
- 原因1: GASのelse分岐が「全社以外を除外」ではなく「関東社員・実績報告以外を全部通す」設計だったため、フィルタの追加前に処理されたデータがトークノート受信録シートに残り、毎時間DBに再同期されていた
- 原因2: else分岐の名前・本文抽出パターンが直接メッセージ専用で、全社ノート投稿に対応していなかった
- 解決: else分岐に「ノートに投稿しました」かつ「全社」でない場合はスキップするガードを追加。全社ノート用の抽出パターン（さんが「全社」、さんの投稿：）を追加
- 再発防止: ノート投稿の振り分けはホワイトリスト方式（全社だけ通す）にする。既存シートの混入データは手動削除が必要

## 2026-07-01: AccessLogパネルのヘッダーがスクロールで流れる
- 症状: アクセスログパネルを開いてスクロールすると、ヘッダー（タイトル・閉じるボタン）が一緒に流れてしまい固定されない
- 原因: パネル全体に `overflowY: auto` が設定されており、ヘッダーとコンテンツが同じスクロール領域に含まれていた（勤続年数・ログイン情報パネルとは構造が異なっていた）

- 再発防止: パネル系UIの構造は「ヘッダー（flexShrink:0）+ スクロール可能なコンテンツ（flex:1, overflowY:auto）」で統一する

## 2026-07-31: 実績報告自動生成でキャリア（au/UQ）不明のMNPが合計から消える
- 症状: 稼働カードの「生成」ボタンで作った実績報告で、実際はMNP26件あるのに「MNP：24」と表示された（本番の畠中さんチームの投稿で発覚）
- 原因: `TalknoteCard.tsx`の`parseJissekiBreakdown`で、全体の新規HS/MNP合計を「au内訳＋UQ内訳」の合算値として算出していた。「入澤身内\nMNP2」のようにau/UQの表記がない投稿はどちらの内訳バケットにも入らず、合計からも丸ごと抜け落ちていた
- 解決: `JissekiBreakdown`に`mnpTotal`／`shinTotal`を追加し、キャリア判定の成否に関わらず全投稿のMNP・新規件数をここに積算。ブース全体実績（新規HS・MNP）はこの全体合計を使い、au/UQ内訳は従来通りキャリア判定できたものだけを振り分ける（内訳の合計と全体の合計が一致しなくなる場合があるのは仕様として許容）
- 再発防止: 「全体合計」と「カテゴリ別内訳」を両方出す集計ロジックを書くときは、全体合計を内訳の合算から逆算しない。パース段階で判定不能なデータが内訳に入らず全体からも消えていないか、境界ケース（キーワードなし投稿等）を必ずテストする

## 2026-07-31: 「Air新規」がau/UQの新規HSに誤カウントされていた
- 症状: 稼働カードのバッジ・実績報告生成の両方で、SB系ブースの「Air新規」（ソフトバンクAirの新規契約、固定商材）が携帯の新規HSとしてカウントされてしまい、数字がズレていた
- 原因: `countShin`の除外リスト（`SHIN_EXCLUDE_PREFIX`）に固定光回線（光・ひかり・Biglobe等）は入っていたが「Air」が入っておらず、「新規」の直前直後にAirが付いていても除外されなかった
- 解決: `SHIN_EXCLUDE_PREFIX`にAir/エアー/エア系のパターンを追加。あわせて「新規」の直後を見る`SHIN_EXCLUDE_SUFFIX`を新設し、前後どちらにAir等が付いていても除外できるようにした（従来は直前のみチェックしていた）
- 再発防止: `countShin`はバッジ表示とジェネレータ両方で共有されている関数なので、除外キーワードを増やすときはこの一箇所を直せば両方に反映される。逆に言えば、ここに固定商材のキーワードを漏らすと両方で誤カウントする

## 2026-07-31: 実績報告生成でMNP・クレカが実際より多くカウントされる不具合（2件複合）
- 症状: 実際の運用（アリオ北砂 7/4）でMNPが13（正しくは10）、クレカが12（正しくは1）と生成された
- 原因1（改行またぎで無関係な数字を拾う）: `DENKI_RE`/`KUREKA_RE`等LD項目の正規表現が、キーワードの後ろの数字を`\s*(\d+)?`で拾っていたが`\s`は改行にもマッチするため、「でんき、クレカ\n11日（土）12:00予約」のように次の行が数字で始まる場合、その数字（11）をクレカの件数として誤って拾っていた
- 原因2（未確定・翌日予定の除外漏れ）: 「明日10:00戻り予定」「◯日（土）◯時予約」のような翌日以降の未確定案件を除外するロジックが直前1行しか見ておらず、お客様名などの行が間に挟まると素通りしていた。またLD項目（電気・ガス・クレカ等）にはそもそも除外ロジックがなかった
- 解決:
  - LD項目系の正規表現はすべて、数字直前の空白を`\s*`ではなく`[ \t　]*`（改行を含まない同一行の空白のみ）に変更
  - 除外キーワードに「予約」を追加。日付マッチングに`[0-9]{1,2}日`（月表記なしの単独の日付）を追加
  - MNP・新規のカウントは、直前1行だけでなく「その一致より前の全文（`before`）」に除外キーワードが含まれるかで判定するよう変更（間に別の行を挟んでも検出できる）
  - LD項目（`countLdItem`）にも同様の除外ロジックを追加。ただし「次の行」までは見ない（「予約」等のマーカーは大抵その後に続く"別の"項目の説明であり、次の行まで見ると手前の無関係な項目まで誤って除外してしまうため。「新規HS」除外の前後チェックとは意図が違う）
- 教訓: 「キーワードの後ろの数字を拾う」正規表現は`\s*`で書くと改行を平気でまたぐ。行をまたいでよい理由がない限り`[ \t　]*`にする。除外ロジックは「メッセージ内のどこで一致が起きたか」に応じて前方参照の範囲を変える必要があり、一律に同じ範囲（前後1〜2行）を適用すると新しいバグを生む
